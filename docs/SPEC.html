1. 목적

게시된 식단을 수집해 카카오톡 질문에 날짜와 끼니에 맞는 메뉴로 답한다.

2. 프로젝트 범위

이번 기준선에 포함: 조회 입력의 날짜 해석, 다음 주 제한, 식단표의 휴무·연휴 안내 구분.

이번 기준선의 확정 범위 밖: 실제 그룹웨어 접근, OCR 정확도 전체, 운영 채널 전송. 기존 기능을 제거하거나 변경한다는 뜻이 아니다.

REQ-OCR-001 공휴일 이름으로 표시한 휴무

implemented구현 src/menu_bot/parser.py, src/menu_bot/query.py테스트 tests/test_holiday_notices.py
변경 이력 3
  • 2026-10-06 REQ-OCR-001: 식단표에 공휴일 이름만 있는 날짜를 세 끼 모두 식당 미운영으로 안내한다. 한글날을 중식 일반식 메뉴로 표시하던 문제를 고쳤다.
  • 2026-10-06 REQ-OCR-001: 공휴일 이름의 띄어쓰기·괄호를 처리한다. 음식이 함께 있는 날짜, 공휴일 특식과 끼니별 미운영 안내는 유지한다.
  • 2026-10-06 REQ-OCR-001: 휴무 이름 20종·표기, 특식 4종, 음식이 있는 날짜와 끼니별 휴무를 확인하는 회귀 테스트를 추가했다.

식단표의 날짜 칸에 한글날이나 개천절만 있고 음식 메뉴가 없으면, 조식·중식·석식 모두 식당 미운영으로 안내한다. 공휴일 이름을 일반식 메뉴로 표시하지 않는다.

  • 이름 안의 띄어쓰기와 이름을 감싼 괄호는 같은 안내로 읽는다.
  • 다른 공휴일도 식단표에 이름만 적혀 있으면 같은 기준을 적용한다.
  • 같은 날짜에 음식 메뉴가 있으면 공휴일 이름만으로 전일 휴무를 결정하지 않는다.
  • 한글날 특식, 추석 송편 같은 음식·행사 문구를 휴무로 바꾸지 않는다.
  • 중식 미운영처럼 끼니를 지정한 안내는 그 끼니에만 적용한다.

REQ-OCR-002 연휴 안내의 범위와 문구 구분

implemented구현 src/menu_bot/service_notices.py, src/menu_bot/parser.py, src/menu_bot/pipeline.py테스트 tests/test_holiday_notices.py
변경 이력 4
  • 2026-10-06 REQ-OCR-002: 설 명절·한가위 연휴·임시 공휴일·대체 휴일과 식당 휴무 문구를 처리한다. 장식 기호·요일·휴무 안내 어미도 구분한다.
  • 2026-10-06 REQ-OCR-002: 같은 날짜에서 가까이 붙은 OCR 조각을 안내 문구로 합친다. 날짜·기간이 붙거나 여러 날짜에 걸친 안내를 해당 날짜별로 처리한다. 잘못된 날짜는 다른 메뉴 수집을 중단하지 않는다.
  • 2026-10-06 REQ-OCR-002: 공휴일 특식을 휴무로 오인하거나 끼니별 미운영을 전일 휴무로 확대하는 문제를 고쳤다. 한 게시물의 다른 이미지에 음식이 있으면 이름만으로 만든 휴무 안내를 제외한다.
  • 2026-10-06 REQ-OCR-002: 회귀 테스트를 71개로 확장했다. 운영 서버의 과거 OCR 캐시 57장에서 정상 메뉴 변경이 없고 현재 운영 항목 154개도 동일함을 확인했다.

설 명절, 한가위 연휴, 대체 휴일, 임시 공휴일도 음식이 없는 날짜의 전일 미운영 안내로 읽는다. 별표나 장식 괄호가 있어도 같은 안내로 처리한다.

  1. 식당 휴무, 전사 휴무처럼 식당 전체를 지정한 안내는 세 끼에 적용한다.
  2. 석식 공휴일 미운영은 석식만, 조식·석식 미운영은 지정한 두 끼니만 처리한다.
  3. 건강식 미운영 같은 코너 안내를 다른 코너나 끼니의 휴무로 확대하지 않는다.
  4. 공휴일 특식, 노동절 특식과 정상 운영 문구는 휴무를 뜻하지 않는다.

같은 날짜 칸에서 가까이 붙어 있는 OCR 조각이 알려진 안내 문구를 이루면 합쳐 읽는다. 다른 날짜의 글자를 이어 붙이거나 잘못 읽은 글자를 추측해 휴일 이름으로 바꾸지 않는다.

날짜가 붙은 안내는 표 안의 해당 날짜에 적용한다. 날짜 범위가 적혀 있거나 안내 글자가 여러 날짜 열에 걸쳐 있으면 해당 열을 각각 판단한다. 이름만 있는 연휴 안내는 음식이 있는 날짜를 휴무로 바꾸지 않는다.

10/08~09는 같은 달의 8일부터 9일까지로 읽는다. 날짜가 틀렸거나 끝 날짜가 시작 날짜보다 이르면 휴무 날짜를 추정하지 않는다. 해당 문구만 건너뛰고 다른 날짜 메뉴는 처리한다.

한 게시물의 여러 이미지를 합칠 때도 음식이 있으면 이름만으로 만든 휴무 안내를 제외한다. 식당 휴무처럼 미운영이 적힌 안내는 유지한다.

한계 휴일 이름이 OCR에서 사라졌거나 글자가 알아볼 수 없게 틀리면 휴무를 확정할 수 없다. 기존 메뉴 없음 안내를 유지하며 달력만 보고 추정하지 않는다.

참고

달력만 보고 휴무를 추정하지 않는다. 이름도 메뉴도 없는 빈 칸은 기존의 메뉴 없음 안내를 유지한다.

9. 오류 처리 정책

모호하거나 지원하지 않는 질문은 날짜나 끼니를 임의 선택하지 않고 안내한다. parser가 날짜를 해석할 수 있어도 answer 단계의 조회 제한을 우회해서는 안 된다.
